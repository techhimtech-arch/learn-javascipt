# BOM

## 1. Definition

The **Browser Object Model (BOM)** allows interaction with the browser window — not part of official specification but widely implemented.

Includes:
- `window` object
- `navigator`
- `screen`
- `location`
- `history`
- `frames`

## 2. Why do we need it?

To access browser-level info, navigate pages, manage sessions, detect environment.

## 3. Internal Working

All BOM APIs expose global-level interfaces provided by browser vendors.

## 4. Step-by-Step Execution

Example:
```javascript
window.addEventListener("resize", () => {
  console.log(`Width: ${window.innerWidth}`);
});
```

Steps:
1. Window fires resize event
2. Listener invoked
3. InnerWidth retrieved from layout state

## 5. Syntax

```javascript
window.method()
navigator.property
location.href
history.back()
```

## 8. Real-world Example

Detecting mobile devices in Angular:
```typescript
@Injectable()
export class DeviceService {
  get isMobile(): boolean {
    return /mobile/i.test(navigator.userAgent);
  }
}
```

## 🔍 Quick Recap
- BOM includes window, navigator, location, history
- Provides browser-level access outside DOM
- Not standardized but consistently implemented
- Used for environment detection/navigation

## 📝 Summary
The BOM interfaces with the browser chrome. The `window` object is central, exposing utilities like `location` and `navigator`. While not formally specified, these APIs enable rich client-side behavior essential to modern web apps.

## 17. Summary
