# BEM

## 1. Definition

**BEM** (Block Element Modifier) is a naming methodology organizing CSS classes around components’ structural relationships.

Structure:
- Block: standalone entity
- Element: child of block
- Modifier: variant/state of block/element

## 2. Why do we need it?

Enforce consistency, prevent style collisions, ease maintainability in large codebases.

## 3. Internal Working

Classes encode hierarchy directly:
```css
.block {}              /* Root */
.block__element {}     /* Child */
.block--modifier {}    /* Variant */
```

No nesting required — flat structure ensures predictable cascade behavior.

## 4. Step-by-Step Execution

Example:
```html
<button class="button button--primary">Primary</button>
<button class="button button--secondary">Secondary</button>
```

```css
.button { padding: 8px 16px; border-radius: 4px; }
.button--primary { background: blue; }
.button--secondary { background: gray; }
```

Steps:
1. Define base `.button` styles
2. Extend with `--primary/--secondary`
3. Apply variant via class attribute
4. No overrides necessary

## 5. Syntax

```
.block
.block__element
.block__element--modifier
.block--modifier
.block__element--state_active
```

## 6. Examples (Easy → Advanced)

### Easy
```css
.card { border: 1px solid #ccc; }
.card__title { font-weight: bold; }
.card__title--highlighted { color: red; }
```

### Medium
```css
.nav { list-style: none; padding: 0; margin: 0; display: flex; }
.nav__item { margin-right: 1rem; }
.nav__link { text-decoration: none; }
.nav__link--active { font-weight: bold; }
```

### Advanced
```scss
// SCSS helper mixins
@mixin bem($block) {
  $class: '.#{$block}';
  #{$class} {
    @content;
  }
}

@include bem(card) {
  &__body { padding: 1rem; }
  &--compact { padding: 0.5rem; }
}
```

## 8. Real-world Example

Angular component using BEM-like pattern:
```html
<div class="user-profile-card user-profile-card--expanded">
  <img class="user-profile-card__avatar" src="..." />
  <h3 class="user-profile-card__name">John Doe</h3>
  <span class="user-profile-card__badge user-profile-card__badge--verified">✓</span>
</div>
```

## 9. Angular Use Case

Component-scoped styling, avoiding `::ng-deep` overuse.

## 10. Common Mistakes

❌ Deep nesting like `.block__elem__subelem`  
❌ Long class names hurting readability

## 11. Edge Cases

1. **Boolean modifiers**
   ```css
   .button.button--disabled {} /* Enabled/disabled states */
   ```

2. **Multi-class combinations**
   ```html
   <div class="card card--featured card--large"></div>
   ```

## 12. Performance Considerations

Flat selectors outperform deeply-nested ones — especially with virtual scrolling.

## 16. Production Best Practices

1. Stick to two levels max (block/element/modifier)
2. Use consistent separators (`__`, `--`)
3. Keep class names short yet descriptive
4. Automate with linters/formatters

## 17. Summary

BEM standardizes component naming — promotes clarity, reuse, and team alignment.

## 18. Revision Notes

- Double underscore for elements
- Double dash for modifiers
- Avoid deep nesting
